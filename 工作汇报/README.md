# 工作汇报

## 组织方式

一个项目一个 Markdown 文件，文件名就是项目简称；日期不单独建文件夹，而是作为文件内部的小节标题。打开一个文件，从上到下就是这个项目的完整时间线。

```
工作汇报/
├── README.md          ← 本文件，项目总览
├── 配电改造.md         ← 一个项目一个文件
└── 厂房照明.md
```

## 项目总览

| 项目 | 状态 | 起止 | 最近更新 | 记录 |
|---|---|---|---|---|
| 暂无 | | | | |

## 新增一个项目

1. 在 `工作汇报/` 下新建 `<项目简称>.md`，例如 `配电改造.md`
2. 复制 `_模板/项目汇报记录.md` 的全部内容粘贴进去
3. 改文件开头的项目信息
4. 回到本文件，在上面的总览表里加一行

## 新增一份汇报

1. 打开对应项目的 `.md`
2. 找到 `## 汇报记录`，把新的 `### YYYY-MM-DD｜类型` 小节**插在它下面第一行**（最新的在最上面）
3. 按模板填六个小节
4. 回本文件，更新总览表里的“最近更新”日期

## 规范

- 文件名：项目简称，如 `配电改造.md`
- 记录标题：`### YYYY-MM-DD｜类型`，类型为 日报 / 周报 / 月报 / 专项
- 提交信息：`汇报: 项目名 YYYY-MM-DD 类型`
- 公开仓库：提交前完成脱敏（客户名、报价、人名、内部编号、图纸和截图一律不写）

## 什么时候拆文件

单个项目文件超过约 2000 行，或者跨年记录变多时，按年份拆成 `配电改造-2026.md`、`配电改造-2027.md`，并在总览表里分别列出。没到这个量就不拆，一个文件最好找。
