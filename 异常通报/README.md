# 异常通报

记录厂站监控后台异常，一事一档：结构化字段便于检索统计，通报原文可直接复制转发，跟踪小节记录闭环过程。

## 目录组织

一个异常一个 Markdown 文件，按年份建子目录。

- 有官方通报号：`<通报号>.md`，如 `GCFK202612995.md`
- 无官方通报号：`<站点缩写>-YYYYMMDD-<序号>.md`，如 `YNHLS-20261115-01.md`，拿到正式通报号后重命名并同步索引

```
异常通报/
├── README.md              ← 本文件，使用规范、模板说明与总索引
└── 2026/
    └── GCFK202612995.md
```

## 使用规范

### 新增一条异常

1. 复制 `_模板/异常通报记录.md` 到 `异常通报/<年份>/<通报号>.md`
2. 填写标题、字段、事件过程、通报原文、跟踪
3. 脱敏自查（见下节），确认无厂站全称、人名全称、截图等敏感内容
4. 在本文件的总索引表加一行
5. 本地提交，确认后再推送

### 更新与闭环

- 同一异常的后续进展（原因查明、措施、复归、闭环）直接修改原文件，不新建文件
- 进展写入 `## 跟踪`，同时更新字段中的 `状态` 和总索引表
- `状态` 由复归情况 + 处理进度组成，例如 `已复归，跟踪中`、`未复归，跟踪中`、`已闭环`

### 提交信息

- 新增：`异常通报: <站点缩写> <通报号>`
- 更新：`异常通报: <通报号> <进展简述>`

## 脱敏规范

| 内容 | 处理方式 | 示例 |
|---|---|---|
| 厂站名称 | 省市 + 站名首字母，保留电压等级 | `HNZMD ±800kV YNHLS` |
| 人名 | 姓名首字母 | `HA` |
| 截图、照片 | 不入库，转成文字记录 | 后台事件列表 → 事件过程表 |
| 图纸、报价、内部系统地址、账号 | 不入库 | — |
| 装置型号、程序版本、管理序号、通报号 | 保留，供技术检索 | `PCS-976A-DTHP-G`、`V6.0` |

补充约定：

- 仓库内不保留「缩写 ↔ 全称」对照表，对照关系线下保存
- `.uploads/` 已加入 `.gitignore`，原始截图不会被提交

## 模板格式

模板文件：[`_模板/异常通报记录.md`](../_模板/异常通报记录.md)，由标题、字段、事件过程、通报原文、跟踪五部分组成。

### 标题

```
# 通报号｜YYYY-MM-DD 站点 设备 异常简述
```

一行说清「哪个站、哪台设备、什么异常」，例如 `# GCFK202612995｜2026-11-15 HNZMD ±800kV YNHLS 第六大组滤波器第4小组保护 AFP64A 装置闭锁后重启`。

### 字段

| 字段 | 说明 |
|---|---|
| 厂站 | 脱敏后的站点名 |
| 设备 | 保护/装置名称及编号 |
| 装置型号、程序版本、管理序号 | 按装置实际信息填写，用于研发定位 |
| 事件等级 | 取本次异常的最高等级（正常 / 告警 / 报警 / 紧急），可括号补充说明 |
| 功率损失 | `无`，或写明损失数值与时长 |
| 状态 | 见「更新与闭环」 |
| 通报号 | 官方通报号，无则填临时编号 |
| 处置 | 一句话说明已采取的措施和责任人（脱敏） |

### 事件过程

按时间顺序填写后台事件，一行一条：

| 时间 | 事件 | 等级 |
|---|---|---|
| HH:MM:SS | 事件描述，信号变位注明「出现 / 消失」 | 后台实际等级 |

跨天时时间列补日期；只记录与本异常相关的事件，无关告警不抄。

### 通报原文

用引用块完整保留通报文本，格式为 `【异常通报】……【通报号】`。**先完成脱敏再粘贴**，与正文字段保持一致。

### 跟踪

- 原因：研发/现场分析结论，未查明时写「待研发分析」
- 措施：已执行或计划的整改措施
- 结论：闭环结论，未闭环留空
